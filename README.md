# Rhythm Master · 基于 FPGA 的数字音乐播放器

> Cyclone IV E (EP4CE6F17C8) · Verilog HDL · Quartus Prime 18.1 Lite
> 课程实践周项目 · 🚧 仍在开发中

用一块 FPGA 开发板 + 一个无源蜂鸣器做出来的**纯硬件音乐播放器**：没有 CPU、没有软件、没有 PWM 外设库，
从分频计数到乐谱查表全部由 Verilog 时序逻辑完成，按下按键就能把一首完整的曲子放出来。

---

## 1. 项目简介

整个播放链路只用三层逻辑：

```
乐谱表(ROM) ──► 周期查表 / 节拍计时 ──► PWM 方波发生器 ──► 蜂鸣器
```

- **音高**：每个音符对应一个"时钟周期数"（50 MHz 晶振下 1 个周期 = 20 ns），计数器数满即翻转电平，
  得到精确频率的方波；
- **节拍**：以 BPM 为基准换算出 1 拍的时钟数，再用音符时值（1/2/4/8/16 分音符）分频，
  决定当前音符保持多久；
- **发声**：50% 占空比方波驱动无源蜂鸣器，方波的谐波足够丰富，听感上就是那个音。

这样做的好处是完全可综合、可移植：换一块板子只要改引脚约束，换一首歌只要改乐谱表。

## 4. 系统结构

```
                  ┌──────────────────────────────────────────┐
    50MHz clk ───►│                                          │
                  │  songData                                │
      replay ────►│   ├─ tones[0..404]  (音符周期表)          │──► tone[25:0] ──┐
                  │   ├─ ttime[0..404]  (音符时值)            │                  │
      enable ────►│   └─ idx 指针 / cnt_t 节拍计数            │                  ▼
                  │                                          │              ┌────────┐
                  │                                          │              │  beep  │──► beepPwm ──► 🔈
                  └──────────────────────────────────────────┘              │  PWM   │
                                                                            └────────┘
```

`main.v` 只做三件事：例化乐谱模块、例化 PWM 模块、把按键接到各自的复位/使能脚。

## 5. 音高与节拍是怎么算的

### 5.1 音高（周期表）

50 MHz 时钟下，标准音 A4 = 440 Hz，一个周期需要 `50_000_000 / 440 ≈ 113636` 个时钟。
于是每个音名都被写成"半周期基准值 × 50"的形式，例如：

```verilog
localparam LDO = 3816 * 50;  // 低音 DO  (261.6 Hz → 191,131 clk)
localparam DO  = 1912 * 50;  // 中音 DO  (523.3 Hz)
localparam HDO = 955  * 50;  // 高音 DO  (1046.5 Hz)
```

同一八度内相邻音名的比例都是 2 的 1/12 次方，所以高八度正好是低八度的一半。

### 5.2 节拍

```verilog
localparam Nowbpm = 8'd64;                    // 每分钟 64 拍
localparam bps    = 50_000_000 / Nowbpm * 60; // 每拍时钟数
```

每个音符的时值字段 `ttime` 用 1/2/4/8/16 表示音符长度，再换算成实际保持的时钟数：

| `ttime` | 含义 | 持续时间 |
| --- | --- | --- |
| 1 | 全音符 | `4 × bps` |
| 2 | 二分音符 | `2 × bps` |
| 4 | 四分音符 | `1 × bps` |
| 8 | 八分音符 | `bps / 2` |
| 16 | 十六分音符 | `bps / 4` |

指针 `idx` 每到时间就把 `tones[idx]` 送到 PWM 模块，走完 404 个音符后 `finish` 拉高、输出静音。

### 5.3 PWM

```verilog
assign pwm = (cnt <= FREQ_T * 50 / 100) ? 1'b1 : 1'b0;  // 50% 占空比
```

计数器在 `0 ~ FREQ_T-1` 之间循环，前半周期输出高、后半周期输出低，得到对应频率的方波。

## 7. 编译与烧录

**环境**：Quartus Prime 18.1 Lite（本工程由 18.1.0 Build 625 生成；Cyclone IV E 需使用带该器件库的版本）。

```bash
# 打开工程
quartus src/rhythmMaster.qpf

# 或者命令行全流程
cd src
quartus_sh --flow compile main
```

烧录：`Tools → Programmer → 选择 bitstream/rhythmMaster.sof → Start`
（也可以先用 `Programmer` 直接把 `sof` 下到 SRAM 里试听，掉电即失效）。

### 仿真验证（可选）

需要 Icarus Verilog：`brew install icarus-verilog`

```bash
cd sim
make beep      # 蜂鸣器：统计每段电平宽度，< 1us 的电平段标成 RUNT（换音毛刺）
make rgb       # 点阵：写入 8x8 测试图案，把输出比特流解码回来逐像素比对
```

两个测试激励都是按"现象量化"写的：不告诉你在哪出错，只把异常的数字打出来——
这正是定位问题的第一步。

## 8. 引脚分配

| 信号 | 引脚 | 说明 |

| `buttons[3]` | PIN_M16 | KEY5（预留） |

## 9. 已知问题（待修）

> 都已经定位到模块，复现方式写在下面。修法留给以后的自己——先自己推一遍，别急着抄答案。

### 9.1 低音区音符音高不对，会出"尖叫"

`songData.v` 里 `tones` 数组是 17 位，但低音区几个周期值已经超出 17 位能表示的范围（最大 131071），
写进去就被截断了，算出来的频率会跑到很高的地方。

影响：乐谱里 `LMI` 用了 5 次（第 48、50、69、87、89 个音符），本该是 330 Hz 的低音咪，
实际发出来接近 2.4 kHz——大概就是那段"有点尖"的来源。

自查：把 `tones` 的位宽和 `LDO` / `LRE` / `LMI` / `LFA` 这几个 `localparam` 的实际数值对一下，
算算要几位才装得下。

### 9.2 换音瞬间的爆音 / 残缺脉冲

单个音符持续时干净，一到换音就有"嗒"的杂音。仿真能量出来：换音那一拍会多出一段极窄的高电平。

```bash
cd sim && make beep     # 出现 !! RUNT ... width=10 ns 就是它
```

排查方向：换音时相位计数器 `cnt` 和新的 `FREQ_T` 是什么关系？新周期更短会发生什么？
另外占空比是组合逻辑算的，换音瞬间的组合毛刺会不会直接传到引脚上？

### 9.3 点阵驱动的像素顺序错乱

`rgbRenderer` 写完还没接顶层，但单独仿真就能看出问题：把 8×8 的测试图案写进去，
再把输出引脚上的比特流解码回来，64 个像素全对不上（整幅图对角偏移，而且第一个像素等于上一帧的最后一个）。

```bash
cd sim && make rgb
```

排查方向：`pix_idx` 自增之后，由它派生的 `tx` / `ty` 在同一拍里读到的是新值还是旧值？
另外 `S_IDLE` 里采样 `curr_pix` 时，`pix_idx` 是不是已经被清零了？

### 9.4 乐谱里有非法时值

第 67、68、69 个音符的 `ttime` 写成了 `5'd12`，而时值编码只有 1 / 2 / 4 / 8 / 16，
落进 `case` 的 `default` 分支被当成四分音符。是笔误还是有意为之，需要回头对一下谱子。

### 9.5 `digitalRenderer` 是空壳

`always` 块里没有内容，输出 `digitalLED` 没有任何驱动，综合时会报"输出无驱动"。

### 9.6 `rgbRenderer` 有 Verilog-2001 不合法的写法

`S_VBLANK` 分支里在无名 `begin...end` 块中声明了 `integer yi, xi;`，这属于 SystemVerilog 语法，
Verilog-2001 不允许。Quartus 18.1 能容忍，但换工具链（比如 `iverilog -g2005`）会直接报错。
另外 `case(state)` 没有 `default` 分支。

### 9.7 按键没有消抖

`replay` / `enable` 直接当复位和使能用，机械按键的抖动会带来多次触发。后面做判定计分时这个问题会被放大。

### 9.8 其它待完成

- 只有一首曲子，乐谱硬编码在 `songData.v` 里（404 个音符）
- `gameController` 只有伪代码，按键判定 / 连击 / 计分 / 结算都未实现
- 点阵、数码管、进度 LED 都没接到顶层
- 上电第一帧 `disp_buf` 是 X，会被当成 0，闪一帧黑
